# Add a body

A body runs in every repo that calls it, so the question to hold throughout is what a repo on a different branch topology, a different runner or a different stack does with it.

## Steps

1. **Name the file `_<name>.yml`.** The underscore marks a file that never runs on its own, keeps the bodies together in the Actions sidebar, and leaves the unprefixed name free for this repository's own stub.

2. **Give it `on: workflow_call` and nothing else.** A body has no trigger of its own. Anything that has to be dispatched, scheduled or fired by a push stays in the stub — a reusable workflow cannot be the target of a `workflow_dispatch`.

3. **Hardcode `runs-on: ubuntu-latest`.** A caller cannot set it, and making it an input has not been needed.

4. **Derive what the repo can answer; take an input only for what it cannot.** The branch topology, the owner and the check list are properties of the calling repo — read them. A version matrix or a language set is not, so those are inputs. See [ADR-0001](../99.adr/0001-derive-a-bodys-configuration-from-the-repo.md).

5. **Declare each secret the body needs under `secrets:`.** Named, never inherited — see [ADR-0003](../99.adr/0003-name-every-secret-a-stub-passes.md).

6. **Choose the job names deliberately.** They are the second half of every caller's check names, so a rename breaks required checks in every calling repo at once. Treat them as a public interface from the first commit, and prefer a name that survives the body growing a job.

7. **Write this repository's own stub for it.** Same filename other repos use, with a local path:

   ```yaml
   jobs:
     promotion-pr:
       uses: ./.github/workflows/_promotion-pr.yml
   ```

   The body then runs here on every change, so a broken one fails at home before it reaches a caller.

8. **Pass every command input through `env:`, never into the `run:` block.** An interpolated `${{ inputs.x }}` becomes part of the script text before the shell parses it, so a value can break out of the command it was meant to be:

   ```yaml
   # wrong — the value is interpolated into the script
   - run: ${{ inputs.build-command }}

   # right — the value stays a value
   - env:
       BUILD_COMMAND: ${{ inputs.build-command }}
     run: bash -c "$BUILD_COMMAND"
   ```

   This holds for anything the caller supplies and for the mutable parts of the `github` context — `ref_name` and `run_number` among them. CodeQL flags the interpolated form as code injection, and it is right to.

9. **Do not call the repository's composite action from the body.** A relative `uses:` resolves against the caller's workspace — see [ADR-0006](../99.adr/0006-keep-the-composite-action-out-of-the-bodies.md). Duplicate the setup steps instead.

10. **Give the concurrency group this body's own name.** In a called workflow `github.workflow` is the _caller's_ name, so two bodies the same caller invokes share one group and cancel each other — the second to start kills the first, and the run reports a job that never ran:

    ```yaml
    concurrency:
      group: ${{ github.workflow }}-ci-laravel-${{ github.event.pull_request.number || github.ref }}
    ```

11. **Run the linters.** `pnpm lint:actions` runs actionlint over every workflow and needs Docker; `pnpm check` runs it as part of the gate.

## Checklist

- [ ] The file is named `_<name>.yml` and its only trigger is `workflow_call`.
- [ ] `runs-on` is fixed in the body, and no caller is asked to supply it.
- [ ] Every input is something the body genuinely cannot read from the repo it runs in.
- [ ] Every secret is declared by name in the body and passed by name in the stub.
- [ ] No `run:` block interpolates an input or a mutable `github` value; each travels through `env:`.
- [ ] The concurrency group names this body, so it cannot cancel a sibling the same caller invoked.
- [ ] Job names are ones you are willing to keep, because renaming one is an estate-wide branch-protection change.
- [ ] This repository carries a stub calling the body by local path, and it has run green.
- [ ] `pnpm check` passes.
