# Migrate a repo to a stub

One repo, one workflow at a time. The file shrinks to a trigger and a `uses:`, and the checks the repo reports change name in the same run — which is the part that breaks something if it is left for later.

## Steps

1. **Replace the body with a stub.** Keep the trigger, delete everything under `jobs:` except the call. A caller job may only carry `name`, `uses`, `with`, `secrets`, `needs`, `if`, `strategy`, `concurrency` and `permissions` — `runs-on` is not allowed there and belongs to the body.

   ```yaml
   # .github/workflows/promotion-pr.yml, complete
   name: Promotion PR
   on:
     push:
       branches: [dev, stage]
   jobs:
     promotion-pr:
       name: Promotion PR
       uses: kirchDev/workflows/.github/workflows/_promotion-pr.yml@<sha> # v0.1.0
   ```

   List `stage` even where no `stage` branch exists: a filter naming a branch that is absent is a no-op, and it keeps the stub identical in every repo.

2. **Pin the SHA, and put the version in a trailing comment.** The tag is what a human reads; the SHA is what runs. Dependabot raises the bumps from there.

3. **Pass the secrets the body needs, by name.** Never `secrets: inherit`.

   | Body                                                                                             | Secret             |
   | :----------------------------------------------------------------------------------------------- | :----------------- |
   | `_queue-branch.yml`, `_fast-forward-queue.yml`, `_release-please.yml`, `_publish-goreleaser.yml` | `BWS_ACCESS_TOKEN` |
   | `_publish-npm.yml`                                                                               | `NPM_TOKEN`        |

   The remaining bodies take no secrets.

4. **Move the branch-protection rule to the new check names.** A called job reports as `<caller-job-name> / <body-job-name>`, so every required check the repo declares changes string. A rule left on the old name waits for a check that will never arrive, and the PR never becomes mergeable.

   Read the body's job names out of the body itself and the caller name out of the stub you just wrote. Two that catch people out:

   - `_fast-forward-queue.yml` reports **four** jobs where the old copies reported three — `Resolve the integration branch` is where the `INTEGRATION_BRANCH` literal went.
   - `_ci-lighthouse.yml` reports one job per shard plus a merge job, where a hand-written audit reported one.

5. **Take the fix that comes with the body.** Some repos are behind rather than different, and the migration is what carries the correction. Check `CLAUDE.md` in this repository for the measured list before opening the PR — a repo on the short queue workflow gains the App-token path it never had, and an npm repo without the prerelease-version fix stops publishing a `dev` version that semver ranks below its own latest release.

6. **Delete the old file's body, not the file.** The stub keeps the filename every other repo uses, which is what makes the estate greppable.

## Three triggers worth fixing while you are here

A migration is the moment the trigger block gets read anyway. Three things in the copied ones cost runner time for nothing, and each is a line:

**Scan on the release branch only.** A push to an integration branch always has a pull request open on it, and that PR run examines the same tree — so `push: branches: [main, dev]` runs the analysis twice for one result. Drop `dev`:

```yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main, dev]
```

**Skip what prose cannot break.** A change touching only Markdown cannot fail a lint or a typecheck:

```yaml
paths-ignore:
  - '**.md'
  - 'docs/**'
```

Never exclude `.github/workflows/**` from a CodeQL trigger — the `actions` language is what scans them.

**Gate the expensive jobs on the tree marker.** Where a repo runs a suite worth minutes, put `_verified.yml` in front of it and record the result at the end. A tree that already passed is then skipped whichever trigger brings it back:

```yaml
jobs:
  verified:
    uses: kirchDev/workflows/.github/workflows/_verified.yml@<sha>

  test:
    needs: verified
    if: needs.verified.outputs.skip != 'true'
    uses: kirchDev/workflows/.github/workflows/_ci-node.yml@<sha>

  record-verified:
    needs: [verified, test]
    if: needs.test.result == 'success'
    uses: kirchDev/workflows/.github/workflows/_record-verified.yml@<sha>
    with:
      tree: ${{ needs.verified.outputs.tree }}
```

> [!IMPORTANT]
> A gated job reports as **skipped**, not as passed. Whether a skipped job satisfies a required check is not verified for this estate — confirm it on one repo before making the marker a rule, or a green run will look blocked.

## Checklist

- [ ] The workflow file contains a trigger and a `uses:`, and nothing else.
- [ ] The `uses:` names a commit SHA with the version as a trailing comment.
- [ ] Every secret the body declares is passed by name; `secrets: inherit` appears nowhere.
- [ ] Every required check in the repo's branch protection matches a `<caller-job> / <body-job>` name that the new run actually reports.
- [ ] A run has completed green on the branch, and the check names in it match the rule.
- [ ] Any fix the body carries for this repo is named in the PR description, so the change is reviewed as a fix rather than a port.
- [ ] The `push` trigger of any analysis workflow names the release branch only, so one change is not scanned twice.
- [ ] A `paths-ignore` covers prose where the workflow cannot be affected by it.
